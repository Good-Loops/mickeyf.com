# Isolated native device validation

The native session bridges pin their backend host. Staging builds must therefore be built separately; changing the web URL alone is not sufficient. Android uses `com.mickeyf.app.staging`. iOS supports a separate Debug identity or an explicitly marked internal-only TestFlight build with the existing `com.mickeyf.app` signing identity. Ordinary release builds retain the production host. Each staging build accepts only its exact configured HTTPS host and the existing method/path allowlist. A missing or invalid host fails closed. Independently verify that the hostname reaches the isolated backend; a hostname suffix cannot prove this.

One zero-cost candidate is a local synthetic-only backend with a temporary local MySQL database and a Cloudflare Quick Tunnel. The repository's `compose.migration-test.yaml` demonstrates an isolated local MySQL setup; the default `compose.yaml` connects to Cloud SQL and is not suitable. Quick Tunnels are public to anyone who knows the URL, terminate HTTPS at Cloudflare and change hostname on restart. They require no inbound port forwarding, but require accepting the service's trust and terms. Restrict the test service to synthetic data, no production credentials, real emails, real child data or enabled external providers; enforce access controls suitable for a noninteractive API, and shut it down afterward. Verify that the backend uses only the isolated database and a non-sending email adapter before any test. Do not create a tunnel or deploy a backend solely on the basis of this note.

Once the backend is qualified, Android uses `VITE_PROD_API_URL=https://<exact-staging-host>`, Capacitor sync and `assembleStaging -PludolumeStagingHost=<exact-staging-host>`. Install only the resulting staging APK for this pass. For iOS, dispatch the existing manual workflow with `internal_staging_host=<exact-Quick-Tunnel-host>`, `upload_testflight=true`, `upload_distribution=internal-only` and the required child UI flags. Leave compile-only, unsigned audit, screenshot and lock-resolution modes false. The signing helper sets `LUDOLUME_INTERNAL_STAGING`, disables provider entry, adds a visible SYNTHETIC label, and verifies the signed web/native origins. It rejects App Store eligible staging exports. The original separate-identity Debug path remains available. Keep the tunnel running throughout the build and device session; restarting changes the hostname and requires another pinned build.

Record the exact device build and isolated backend source. Exercise the remaining native parent list, warning/Keep, daily-limit consent, usage and withdrawal paths using fictional accounts and real HTTP/SQL handlers. Reuse the completed server deadline, delivery, recovery and retry qualification; do not repeat those scenarios on every device. Provider entry and new registration remain closed in this fixture. Inspect the resulting synthetic state and clean up after the device session. This qualifies native management behavior, not real provider identity, email delivery or production routing.

For release acceptance, independently build the exact reviewed source with production settings, install iOS through a current signed TestFlight build and Android through Play's appropriate track, and verify provider callbacks, login, guest play and permissions on the actual devices. App Store and Play console status, submission readiness, Google closed-testing eligibility and physical device results require their own current checks. A debug APK does not establish the Play signing identity. Track iPad acceptance separately when iPad distribution is enabled.

References: [Cloudflare Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/), [Apple developer account and on-device testing](https://developer.apple.com/help/account/basics/about-your-developer-account), [Android command-line device builds](https://developer.android.com/build/building-cmdline).
